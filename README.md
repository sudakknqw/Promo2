# Sharp Barber Bangkok

Одностраничный сайт вымышленного барбершопа в Бангкоке с онлайн-записью.
**Демо-проект: бизнес не настоящий**, контакты и адрес — заглушки.

Сайт работает на двух языках (`/en`, `/th`), принимает записи в Supabase, проверяет занятые слоты,
считает стоимость нескольких услуг на сервере и присылает владельцу уведомление в Telegram
с кнопками подтверждения.

## Возможности

- Лендинг: шапка, hero, услуги, мастера, форма записи, отзывы, «Как найти» с картой, подвал.
- Форма записи: несколько услуг с итогом, выбор мастера, дата и время, комментарий.
- Автоподстановка ближайшего свободного времени при открытии формы.
- Проверка занятых слотов с учётом длительности услуг и мастера; защита от одновременной записи на одно время.
- Серверная валидация, honeypot и ограничение частоты запросов.
- Уведомление в Telegram с кнопками **Confirm** / **Cancel**, которые меняют статус записи в базе.
- Кнопка «Add to calendar» (Google Calendar) после успешной записи.
- Запись через WhatsApp и LINE с готовым текстом сообщения.
- Две языковые версии с переключателем, который сохраняет форму и позицию прокрутки.
- Mobile-first вёрстка, тёмная палитра (графит, беж, охра).

## Быстрый старт

```bash
npm install
```

1. Скопируйте `.env.example` в `.env.local` и заполните значения (см. [Переменные окружения](#переменные-окружения)).
2. Создайте таблицу: выполните `supabase/schema.sql` в Supabase → **SQL Editor**.
3. Запустите:

```bash
npm run dev
```

Сайт откроется на http://localhost:3000 (перенаправит на `/en`).

## Переменные окружения

Все переменные читаются **только на сервере**. В клиентский код они не попадают
(модули в `lib/server/*` импортируют `server-only` — сборка упадёт, если такой модуль окажется в браузере).

| Переменная | Обязательна | Где используется | Примечание |
| --- | --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | да | `lib/server/supabase.ts` | URL проекта Supabase. Можно назвать `SUPABASE_URL` — он в приоритете |
| `SUPABASE_SERVICE_ROLE_KEY` | да | `lib/server/supabase.ts` | ключ `sb_secret_…`. **Никогда** не добавляйте префикс `NEXT_PUBLIC_` |
| `TELEGRAM_BOT_TOKEN` | для уведомлений | `lib/server/telegram.ts` | токен от @BotFather |
| `TELEGRAM_CHAT_ID` | для уведомлений | уведомления и вебхук | чат, куда приходят записи; нажатия кнопок принимаются только из него |
| `TELEGRAM_WEBHOOK_SECRET` | для кнопок | `app/api/telegram/webhook/route.ts` | случайная строка; должна совпадать с `secret_token` в `setWebhook` |
| `NEXT_PUBLIC_SITE_URL` | нет | `app/[locale]/layout.tsx` | базовый адрес для canonical и hreflang. На Vercel не нужен: берётся `VERCEL_PROJECT_PRODUCTION_URL` |

Сгенерировать секрет для вебхука:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Если Telegram-переменных нет, запись всё равно сохраняется — в логах будет предупреждение.

## База данных

### Таблица `bookings`

| Колонка | Тип | Описание |
| --- | --- | --- |
| `id` | uuid | первичный ключ, `gen_random_uuid()` |
| `created_at` | timestamptz | время создания |
| `name` | text | 2–60 символов |
| `phone` | text | нормализованный номер |
| `service` | text | читаемая сводка: `Signature Haircut + Beard Trim & Shape` (для совместимости) |
| `services` | jsonb | снимок услуг на момент записи: `[{ "id", "name", "price", "duration" }]` |
| `total_price` | integer | сумма в батах, посчитана на сервере |
| `total_duration` | integer | длительность в минутах |
| `barber` | text | английское имя мастера или `Any available barber` |
| `booking_date` | date | дата по Бангкоку |
| `booking_time` | time | время начала по Бангкоку |
| `comment` | text | до 500 символов, может быть пустым |
| `status` | text | `new` (по умолчанию), `confirmed`, `completed`, `cancelled`, `no_show` |

### Безопасность

- RLS включён, **политик нет**: роли `anon` и `authenticated` не видят и не могут менять ни одной строки.
- Дополнительно у них отозваны все права на таблицу.
- Сервер работает через `service_role`, который обходит RLS. Браузер к Supabase напрямую не обращается.

### Новая база

Выполните `supabase/schema.sql` целиком.

### Существующая база: миграция 002 (несколько услуг)

Порядок важен, иначе запись на сайте сломается:

1. **Часть A** из `supabase/migrations/002_multiple_services.sql` — **до** деплоя кода.
   Добавляет колонки, расширяет лимит `service`, переносит старые записи.
2. Деплой кода.
3. **Часть B** (в файле закомментирована) — **после** деплоя. Делает колонки обязательными и добавляет проверки.

Проверка после части A (должна вернуть 0 строк):

```sql
select id, service, created_at from public.bookings where services is null;
```

### Полезные запросы

```sql
-- последние записи
select created_at, name, phone, service, total_price, total_duration, barber,
       booking_date, booking_time, status
from public.bookings
order by created_at desc
limit 20;

-- записи на конкретный день
select booking_time, barber, service, total_duration, status
from public.bookings
where booking_date = '2026-09-20' and status not in ('cancelled', 'no_show')
order by booking_time;

-- вручную отметить визит завершённым
update public.bookings set status = 'completed' where id = '<uuid>';
```

Записи со статусами `cancelled` и `no_show` не занимают слот.

## Как работает запись

```
BookingForm (браузер)
   │  POST /api/booking  { name, phone, services: ["haircut"], barber, date, time, comment, locale, website }
   ▼
Route Handler (Node.js)
   1. лимит: 5 запросов с одного IP за 10 минут                  → 429
   2. Origin с чужого сайта, не JSON, тело > 10 КБ               → 403 / 415 / 413
   3. заполнено скрытое поле website (honeypot)                   → 200 без сохранения
   4. validateBooking(): все поля, цены по прайсу                  → 400 + коды ошибок
   5. слот ещё свободен? (по активным записям на эту дату)          → 409
   6. insert в Supabase через service role                         → 500 (детали только в логах)
   7. повторная проверка после вставки (защита от гонки)            → 409, своя запись удаляется
   8. уведомление в Telegram (таймаут 5 с, ошибка не видна клиенту)
   9. ответ 200 с деталями записи
```

### Правила валидации (`lib/validation.ts`)

| Поле | Правило |
| --- | --- |
| Имя | 2–60 символов; буквы любого алфавита (включая тайские с диакритиками), пробел, `-`, `'`, `’`, `.` |
| Телефон | тайский `0XX XXX XXXX` / `02 XXX XXXX` или международный `+` и 8–15 цифр |
| Услуги | от 1 до 6 id из прайса; неизвестные id и объекты отклоняются, повторы считаются один раз |
| Мастер | id из `BARBERS` или `any` |
| Дата | реальная дата, не в прошлом, не дальше 90 дней (по Бангкоку) |
| Время | по сетке 30 минут, в часы работы, весь визит должен закончиться до закрытия; сегодня — не раньше чем через 30 минут |
| Комментарий | до 500 символов, управляющие символы вырезаются |

Сервер возвращает не тексты, а коды: `{ "time": { "code": "closedServices", "params": { "open": "11:00", "close": "18:00" } } }`.
Форма показывает их на языке страницы (секция `validation` в словарях).

### Защита от одновременной записи

Проверка «слот свободен» перед вставкой не спасает, если два человека отправили форму в одну секунду.
Поэтому после вставки сервер перечитывает день и учитывает только записи, созданные **раньше** своей.
Если одна из них конфликтует — своя запись удаляется и клиент получает 409. Из двух одновременных записей
всегда остаётся ровно одна. Форма в этом случае сама подставляет следующее свободное время.

## Слоты и доступность

Логика — в `lib/availability.ts`. Модель: **каждый мастер — одно кресло**.

- Запись к конкретному мастеру занимает этого мастера на всю длительность.
- Запись «к любому мастеру» занимает одно кресло, но не конкретного мастера.
- Мастер свободен, если у него нет пересекающейся записи **и** в каждый момент визита остаётся хотя бы одно свободное кресло.
- «Любой мастер» свободен, если свободен хотя бы один мастер на всё время визита.
- Интервалы полуоткрытые: 14:00–14:30 и 14:30–15:00 не пересекаются.

Длительность записи берётся из `total_duration`. Для записей, созданных до миграции 002, — по названию услуги,
а если название не найдено — 60 минут.

Часы работы:

| День | Часы |
| --- | --- |
| Пн–Чт | 10:00–20:00 |
| Пт–Сб | 10:00–22:00 |
| Вс | 11:00–18:00 |

Время везде считается по Бангкоку (UTC+7, летнего времени нет).

В форме занятое время показывается неактивным с пометкой `booked`. Если свободного времени на день нет —
«Fully booked, try another day» и кнопка ближайшей свободной даты (поиск на 14 дней вперёд).

## Ближайший свободный слот

`GET /api/availability/next` ищет самое раннее свободное время:

- от **текущего момента на сервере** (часы браузера не используются);
- не раньше чем через **60 минут** (клиент должен успеть доехать);
- в пределах **14 дней** (включая сегодня);
- с учётом выбранных услуг (суммарная длительность) и мастера.

Форма подставляет это время при открытии и пересчитывает при смене услуг или мастера.
Над полями — подпись «Nearest available: today 15:30 · choose another time».
Как только пользователь сам меняет дату или время, автоподстановка отключается и больше ничего не перезаписывает.

> Буфер 60 минут действует только для подсказки. В ручном списке можно выбрать время через 30 минут
> (`LIMITS.leadTimeMin`).

## Несколько услуг и цены

- **Прайс хранится в одном месте** — `SERVICES` в `lib/data.ts`.
- Форма отправляет только id: `services: ["haircut", "beard"]`.
- Сервер **не читает** цены и итоги из запроса: `validateBooking` → `quoteServices` пересчитывает сумму
  и длительность по прайсу и сохраняет в базу именно их.
- Итог под списком услуг («2 services · 75 min · ฿900») считается в браузере теми же функциями — только для показа.
- На мобильном блок итога прилипает к низу экрана, пока прокручивается список.

## Добавление в календарь

После успешной записи — кнопка «Add to calendar» (`lib/calendar.ts`):

- время начала переводится из времени Бангкока в UTC (`bangkokToUtc`), окончание = начало + длительность;
- ссылка `calendar.google.com/calendar/render` с параметрами `dates` в UTC и `ctz=Asia/Bangkok`;
- название «Sharp Barber — <услуги>», место — адрес салона, описание — мастер и телефон салона;
- тексты на языке страницы.

## Запись через мессенджер

Блок «or book in one message» под формой (`components/MessengerBooking.tsx`, `lib/messenger.ts`):

- **WhatsApp**: `https://wa.me/<номер>?text=<текст>`, текст кодируется `encodeURIComponent`.
- **LINE**: `https://line.me/R/ti/p/%40<id>` — текст туда передать нельзя, поэтому рядом показан
  готовый текст с кнопкой «Copy».
- Текст собирается из выбранного в форме: услуги, мастер, дата и время, имя. Если ничего не выбрано —
  «Hi! I'd like to book an appointment.» На тайской версии сообщение на тайском.
- Кнопки **не создают запись** — это просто переход в мессенджер.

Номер и LINE ID — в `MESSENGERS` (`lib/data.ts`). Сейчас там вымышленные значения.

## Telegram: уведомления и кнопки

### Уведомление

После каждой записи бот отправляет в `TELEGRAM_CHAT_ID` сообщение **всегда на английском**:
версия сайта (`Site version: Thai (/th)`), услуги с ценами, итог, мастер, дата и время, имя, телефон, комментарий.
Под сообщением — кнопки **Confirm** и **Cancel**.

### Кнопки

Нажатие отправляет `callback_query` на `POST /api/telegram/webhook`. Обработчик:

1. сверяет заголовок `X-Telegram-Bot-Api-Secret-Token` с `TELEGRAM_WEBHOOK_SECRET` (иначе 401);
2. принимает нажатия только из чата `TELEGRAM_CHAT_ID`;
3. проверяет `callback_data`: `confirm:<uuid>` или `cancel:<uuid>`;
4. меняет статус **только из `new`** одним запросом (двойное нажатие сработает один раз);
   если запись уже обработана — отвечает «Already confirmed» / «Already cancelled»;
5. показывает всплывающий ответ, убирает кнопки и дописывает «✅ Confirmed» или «❌ Cancelled».

Подтверждённую запись кнопками отменить нельзя — такие изменения делаются в Supabase.

### Установка вебхука (один раз, на продакшен-домен)

Нужен именно домен из Vercel → **Settings → Domains**: preview-адреса закрыты авторизацией Vercel.
Команды для PowerShell, выполнять в одном окне:

```powershell
$token = (Read-Host "TELEGRAM_BOT_TOKEN").Trim()
```

```powershell
$secret = (Read-Host "TELEGRAM_WEBHOOK_SECRET").Trim()
```

```powershell
$url = "https://ВАШ-ДОМЕН.vercel.app/api/telegram/webhook"
```

```powershell
$body = @{ url = $url; secret_token = $secret; allowed_updates = @("callback_query"); drop_pending_updates = $true } | ConvertTo-Json
```

```powershell
Invoke-RestMethod -Method Post -Uri "https://api.telegram.org/bot$token/setWebhook" -ContentType "application/json" -Body $body
```

Ожидаемый ответ: `ok: True`, `description: Webhook was set`.

Проверка:

```powershell
Invoke-RestMethod -Uri "https://api.telegram.org/bot$token/getWebhookInfo" | Select-Object -ExpandProperty result
```

Всё в порядке, если `url` — ваш адрес, `allowed_updates` — `{callback_query}`, `pending_update_count` — 0,
и нет строки `last_error_message`.

Отключить кнопки:

```powershell
Invoke-RestMethod -Method Post -Uri "https://api.telegram.org/bot$token/deleteWebhook"
```

Вебхук у бота один: нажатия приходят на продакшен, даже если уведомление отправил локальный сервер.
Это работает, потому что база общая.

## Языки: /en и /th

### Как устроено

- Маршруты: `app/[locale]` с языками `en` и `th` (`lib/i18n/config.ts`). `/` → 307 на `/en` (`next.config.mjs`).
- `<html lang>` меняется по языку; у каждой версии свои `title`, `description`, `canonical`
  и `hreflang`-ссылки (`en`, `th`, `x-default`).
- Все тексты — в `dictionaries/*.json`. В компонентах строк нет.
- Серверные компоненты получают словарь пропсом, клиентские — через `useI18n()`.
  В браузер уходит только словарь текущего языка.
- Английские названия услуг и имена мастеров (для базы и Telegram) читаются из `en.json`.
- Неизвестные пути: `/en/foo` и `/th/foo` показывают локализованную 404, `/de` — английскую.

### Как добавить или изменить текст

1. Добавьте ключ в **оба** файла: `en.json` и `th.json`.
2. Плейсхолдеры в фигурных скобках (`{name}`, `{phone}`) должны совпадать в обоих языках.
3. В серверном компоненте: `dict.секция.ключ`; в клиентском: `const { dict } = useI18n()`.
4. Для подстановки значений: `interpolate(dict.common.callUsAt, { phone })` из `lib/i18n/text.ts`.

Если в `th.json` не хватает ключа, `npm run typecheck` и сборка упадут
(`lib/i18n/dictionaries.ts` проверяет тайский словарь по типу английского).

### Как добавить третий язык

1. Добавьте код в `LOCALES` (`lib/i18n/config.ts`).
2. Создайте `dictionaries/<код>.json` по образцу `en.json` и подключите его в `lib/i18n/dictionaries.ts`.
3. Добавьте язык в `alternates.languages` (`app/[locale]/layout.tsx`) и в секцию `language` всех словарей.
4. Если нужен особый формат дат — ветка в `formatDate` / `formatShortDate` (`lib/i18n/text.ts`).
5. Если для алфавита нужен свой шрифт — подключите его в `app/[locale]/layout.tsx` и добавьте в `LOCALE_FONTS`
   (`lib/i18n/locale-switch.ts`).

### Форматы

| | EN | TH |
| --- | --- | --- |
| Дата | Wed, 16 Sept 2026 | วันพุธ 16/09/2026 (григорианский год) |
| Время | 18:30 | 18:30 |
| Длительность | 1 h 15 min | 1 ชม. 15 นาที |
| Цена | ฿850 | ฿850 |
| Телефоны | не переводятся | не переводятся |

### Тайская типографика

- Шрифт Noto Sans Thai с `subsets: ['thai', 'latin']` — латиница внутри тайского текста выглядит так же.
- Для `:lang(th)` в `app/globals.css`: межстрочный интервал текста 1.7, заголовков 1.35,
  без `letter-spacing` (разрядка отрывает тайские диакритики от букв), заголовки с `text-wrap: balance`.
- В тайском нет пробелов между словами; переносы делает браузер. Вёрстка проверена на ширине 320 и 375 px.

### Переключатель языка

- В шапке — сегменты **EN / TH**. Это обычные ссылки: работают без JavaScript, Ctrl/Cmd-клик открывает новую вкладку.
- На экранах уже 480 px текст логотипа скрыт, остаются ножницы — иначе переключатель не помещается.
- При обычном клике ничего не прыгает:
  1. сохраняется элемент, который виден под шапкой, и насколько он прокручен;
  2. сохраняется состояние формы: значения, ошибки, загруженные слоты, найденное ближайшее время;
  3. загружаются шрифты другого языка (ожидание не дольше 0,8 с);
  4. страница меняется, форма сразу рисуется в сохранённом состоянии, прокрутка восстанавливается до отрисовки.
- Данные лежат в `sessionStorage` (`sharp:locale-switch:*`) не дольше 30 секунд и удаляются сразу после восстановления.

## Справочник API

Все ответы — JSON с `Cache-Control: no-store`.

### `POST /api/booking`

Тело:

```json
{
  "name": "Somchai Jaidee",
  "phone": "081 234 5678",
  "services": ["haircut", "beard"],
  "barber": "any",
  "date": "2026-09-16",
  "time": "14:00",
  "comment": "",
  "locale": "en",
  "website": ""
}
```

| Код | Когда | `code` в ответе |
| --- | --- | --- |
| 200 | запись создана | — (`booking`: имя, телефон, услуги, итоги, мастер, дата, время, комментарий) |
| 400 | ошибки полей | `invalid_fields` + `fieldErrors` |
| 400 / 403 / 413 / 415 | битый JSON, чужой Origin, большое тело, не JSON | `invalid_request` |
| 409 | время уже занято | `slot_taken` |
| 429 | больше 5 запросов за 10 минут | `rate_limited` + заголовок `Retry-After` |
| 500 | ошибка базы | `server_error` |

### `GET /api/availability?date=YYYY-MM-DD[&days=N]`

Занятые интервалы на дату (или диапазон `days` = 1–31). Отдаёт **только** дату, время, id мастера
и длительность — без имён, телефонов и комментариев.

```json
{ "ok": true, "date": "2026-09-20", "until": "2026-10-03",
  "busy": [{ "date": "2026-09-20", "time": "12:30", "barber": "krit", "durationMin": 30 }] }
```

Ошибки: 400 (неверная дата, в прошлом, дальше 90 дней, неверный `days`), 429 (больше 60 запросов за 10 минут), 500.

### `GET /api/availability/next[?services=haircut,beard][&barber=any]`

```json
{ "ok": true, "today": "2026-09-15", "searchedUntil": "2026-09-28", "durationMin": 75,
  "slot": { "date": "2026-09-15", "time": "18:30" } }
```

`slot: null`, если за 14 дней свободного времени нет.
Ошибки: 400 (неизвестная услуга, больше 6 услуг, неизвестный мастер), 429, 500.

### `POST /api/telegram/webhook`

Только для Telegram. Без правильного заголовка `X-Telegram-Bot-Api-Secret-Token` — 401.
Битый JSON — 400, тело больше 100 КБ — 413. Во всех остальных случаях — 200 (чтобы Telegram не повторял запрос).

## Деплой на Vercel

1. Переменные окружения: Vercel → проект → **Settings → Environment Variables** (окружения Production и Preview).
2. Отправьте изменения в GitHub (`git push`) — Vercel задеплоит автоматически.
3. После **изменения переменных окружения** нужен **Redeploy**: Deployments → ⋯ → Redeploy.
   Новые переменные подхватываются только новым деплоем.
4. Если в релизе есть миграция базы — соблюдайте порядок из раздела [База данных](#база-данных).
5. Для кнопок в Telegram — один раз [установите вебхук](#установка-вебхука-один-раз-на-продакшен-домен).

В `app/[locale]/layout.tsx` стоит `robots: noindex` — это демо. Для настоящего сайта уберите.

## Частые проблемы

| Симптом | Причина | Что сделать |
| --- | --- | --- |
| Форма пишет «Something went wrong…», в логах `PGRST205` | таблица не создана или в другом проекте Supabase | выполните `schema.sql` в проекте из `NEXT_PUBLIC_SUPABASE_URL`, или `notify pgrst, 'reload schema';` |
| В логах `42703` / `PGRST204` | миграция 002 не выполнена | выполните часть A миграции |
| На Vercel ошибка, локально всё работает | нет переменных окружения на Vercel | добавьте их и сделайте Redeploy |
| «Supabase server environment variables are not configured» | не задан URL или ключ | проверьте `.env.local` / переменные на Vercel |
| «Too many booking attempts» | 5 отправок за 10 минут с одного IP | подождите 10 минут или перезапустите сервер локально |
| Уведомления не приходят | нет `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` или бот не добавлен в чат | проверьте переменные; в логах `[telegram]` |
| Кнопки в Telegram «крутятся» и ничего не происходит | вебхук не установлен или секрет не совпадает | `getWebhookInfo` → `last_error_message`; при 401 сверьте секрет и сделайте Redeploy |
| В логах `rejected callback from chat …` | нажатие не из `TELEGRAM_CHAT_ID` | проверьте ID чата на Vercel |
| Сборка падает после обновления зависимостей | TypeScript 6 | верните `typescript@5` |
| Сборка падает с ошибкой про ключи словаря | в `th.json` нет ключа из `en.json` | добавьте недостающий ключ |

## Ограничения и что можно улучшить

- **Лимит запросов хранится в памяти процесса.** На Vercel у каждого инстанса свой счётчик.
  Для настоящего продакшена — Upstash Redis или аналог.
- **Занятость старых записей** частично определяется по английским названиям услуг и именам мастеров.
  Переименование в `en.json` влияет на записи, созданные до миграции 002, и на сопоставление мастеров.
- **Буфер 60 минут** действует только для подсказки ближайшего времени, ручной выбор — от 30 минут.
- **Сочетания услуг не ограничены**: можно выбрать, например, комбо и отдельную стрижку одновременно.
- **Статус меняется кнопками только из `new`**; остальные изменения — вручную в Supabase.
- **Контакты вымышленные**: телефон, WhatsApp, LINE ID, соцсети, адрес.
- **Файл `.ics`** для Apple Calendar и Outlook пока не сделан (есть только Google Calendar).
- **Перевод на тайский** стоит проверить с носителем языка.
